# Final Prompt: Price Monitoring Web Scraper Bug Fix & Complete Validation

## Role & Objective

You are a senior software engineer tasked with fixing a critical JSON parsing bug in a price monitoring web scraper project, creating a complete fixed project with proper structure and documentation, and executing comprehensive validation to ensure the fix works correctly and meets all requirements.

## Input & Context

**Project Details:**
- Buggy project source: `issue_project/` in the workspace root
- Target workspace: `<WORKSPACE>` directory (e.g., C:\BugBash\workSpace1)
- Fixed project destination: `<WORKSPACE>/grok-fast/issue_project_fixed/`
- Bug symptom: JSON parser crashes with `JSONDecodeError` when servers return HTML or plain text instead of JSON
- Root cause: Response parser does not validate content-type before calling `json.loads()`
- Impact: 5 of 14 tests fail; application cannot handle non-JSON responses gracefully

## Step-by-Step Instructions

### Phase 1: Analyze Bug & Create Fixed Project

**Step 1.1: Analyze Failing Tests**
- Read the buggy project's test files to identify which 5 tests are failing
- Understand what exceptions the tests expect to be raised
- Identify specific parser methods that crash
- Document the gap between current behavior and expected behavior

**Step 1.2: Inspect Buggy Source Code**
- Examine `src/parser.py` in the original project
- Locate where `json.loads()` is called without content-type validation
- Review response object structure and available data (headers, content-type, body)
- Determine how to detect and properly handle non-JSON responses

**Step 1.3: Fix the Parser Implementation**
- Modify only `src/parser.py` to add content-type validation
- Add logic to check `response.headers['Content-Type']` for JSON indicators
- Implement fallback detection for HTML/plain-text responses when headers are missing
- Raise `ValueError` (not `JSONDecodeError`) for non-JSON responses with clear messages
- Error messages must mention both "json" and actual content-type (e.g., "Expected JSON response but got text/html")
- Preserve existing behavior: `json.JSONDecodeError` for malformed JSON with proper content-type
