## Step-by-Step Instructions

### Phase 1: Analyze Bug & Create Fixed Version

**Step 1.1: Analyze the Bug**
- Read all test files (`tests/test_parser.py`, `tests/test_scraper.py`) to understand expected behavior
- Identify which 5 tests are failing and what exceptions they expect
- Analyze `src/parser.py` to locate where `json.loads()` is called without content-type validation

**Step 1.2: Locate Problem Area**
- Find the `ResponseParser.parse_response()` method
- Understand what information is available in the response object (headers, body, content-type)
- Determine how to distinguish JSON from HTML/plain-text before attempting parsing

**Step 1.3: Implement Minimal Fix**
- Modify ONLY `src/parser.py` to add content-type validation
- Check `response.headers['Content-Type']` for JSON-related content types
- Implement fallback heuristics to detect HTML/plain-text content if headers are missing
- Raise `ValueError` (not `JSONDecodeError`) for non-JSON responses with clear, helpful messages
- Preserve existing behavior: `json.JSONDecodeError` for legitimate JSON content with malformed body
