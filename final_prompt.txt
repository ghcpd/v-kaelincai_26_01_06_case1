## Role & Objective

You are a senior software engineer responsible for fixing a critical JSON parsing bug in a Python web scraper project and executing comprehensive validation to ensure the fix is complete, functional, and meets all requirements.

**Project Details:**
- Source project location: `issue_project/` (buggy version)
- Target workspace: `<WORKSPACE>` directory (e.g., C:\BugBash\workSpace3)

- Alternative target name: `oswe-mini-m23a3s430/` (when specified)
- Bug symptoms: 5 of 14 tests failing; `JSONDecodeError` crashes when servers return HTML or plain text
- Original problem: Response parser lacks content-type validation

## Step-by-Step Instructions

### Phase 1: Bug Analysis & Fix Implementation

**Step 1.1: Analyze the Failing Tests**
- Examine `tests/test_parser.py` to identify which 5 tests fail
- Understand what exceptions tests expect to be raised

- Document the gap between expected and actual behavior

**Step 1.2: Locate Bug in Source Code**
- Read `src/parser.py` to find where `json.loads()` is called
- Identify where content-type validation is missing
- Examine response object structure (headers, content, body)
- Determine how to detect non-JSON responses (HTML, plain text)

**Step 1.3: Implement Fix in parser.py**
- Add content-type checking logic before `json.loads()` call
- Check `response.headers['Content-Type']` for JSON indication
- Implement fallback heuristics for HTML/plain-text detection when headers missing
- Raise `ValueError` (not `JSONDecodeError`) for non-JSON responses with clear messages
- Ensure error messages mention both "json" and actual content-type
- Preserve existing `json.JSONDecodeError` for malformed JSON with correct content-type
